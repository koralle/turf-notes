# Turf Notes 要件定義書

最終更新: 2026-10-26ステータス: 合意済み（未決事項を除く）

## 1. 目的

競馬についての個人的なメモを書き溜め、後から引き出せるようにする。レース当日に書いた短い観察も、後から振り返る長い考察も、同じ入れ物に入る。整理はタグとレース情報で行い、メモ同士を参照でつなぐ。

**競馬の事実データ（出馬表・オッズ・結果・払戻）は扱わない。** ユーザーが書いたテキストと、それを整理するための最小限のメタデータだけを持つ。

## 2. 前提と制約

| 項目     | 内容                                                        |
| -------- | ----------------------------------------------------------- |
| 利用者   | 1人のみ。マルチユーザーは対象外                             |
| 公開範囲 | 公開URLにデプロイするが、認証必須。全ページがサインイン必須 |
| 入力     | すべて手入力。外部データの取り込みは行わない                |
| 端末     | PC・スマートフォンの両方。オフライン対応は行わない          |

外部データを取り込まない理由は、①JRA-VAN は Windows 専用の ActiveX 経由でしか配信されず Cloudflare Workers から利用できない、②JRA 公式・netkeiba は API を提供せず、自動取得は利用規約で制限されている、③このアプリの主役は事実ではなくユーザーの主観である、の3点。

## 3. 用語

`GLOSSARY.md` を正とする。主要な用語のみ再掲する。

- **Memo** — ユーザーが書き残す記録の単位。同一性は MemoId
- **Title** — Memo の任意の表題。未入力なら本文1行目を表示上の見出しにする
- **MemoLink** — Memo から Memo への参照。保存は方向を持つ
- **Tag** — Memo に付けるラベル。種類は **馬 / 人 / 主題** の3種
- **Race** — Memo が指す競走。**開催日・競馬場・レース番号の3つ組**で同定され、独立した ID を持たない

## 4. ドメインモデル

### 4.1 Memo

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| 本文 | 必須 | 1文字以上。Markdown 記法で保存し、表示時にレンダリングする |
| タイトル | 任意 | 未入力なら本文の1行目を一覧・参照の見出しに使う。同一性には関与しない |
| タグ | 任意 | 最大20個。種類は馬 / 人 / 主題 |
| レース情報 | 任意 | 0個または1個。§4.3 |
| 参照 | 任意 | 複数の Memo を指せる。§4.4 |
| 投稿日時 | 自動 | 作成日時。一覧の並び順に使う |

### 4.2 Tag

- 種類（kind）は **馬 / 人 / 主題** の3種。人には騎手と調教師を含み、両者を区別しない
- 名前は表示形（display）と正規化形（normalized）の組で持つ。正規化形で一意性を判定する（pantry の ADR-0001 と同じ方式）
- 馬・人・競馬場の専用エンティティは作らない。すべて Tag で表す

### 4.3 Race

独立したテーブルも ID も作らない。Memo が次の4項目を持ち、**同じ3つ組を持つ Memo をまとめた表示**がレースページになる。

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| 開催日 | 必須（レース情報を持つ場合） | レースが行われる日 |
| 競馬場 | 必須（同上） | 中央10場と主要な地方競馬場から選ぶ |
| レース番号 | 必須（同上） | 1つの競馬場・1日における順番 |
| レース名 | 任意 | 平場では条件を書く（例: `3歳未勝利 芝1800`）。同定には使わない |

判断の根拠は `docs/adr/0001-race-as-composite-key.md`。

### 4.4 MemoLink

- 1つの Memo から複数の Memo を参照できる
- 保存は**方向つき**（参照元 → 参照先）
- 表示は**両方向**。参照先の Memo を開くと「このメモを参照しているメモ」が出る
- 関係の種類やラベルは持たない。説明は本文に書く

## 5. 機能要件

### 5.1 認証

| ID | 要件 |
| --- | --- |
| FR-A1 | ユーザーは CLI で作成する。サインアップ画面は作らず、**サーバー側でもサインアップを無効化する** |
| FR-A2 | サインイン画面は**パスキーを既定**の手段とする。「その他の方法でログインする」を展開するとパスワードサインインが現れる |
| FR-A3 | 設定画面で**パスワードサインインの有効／無効を切り替えられる**。無効中はサーバー側でもパスワードを受け付けない |
| FR-A4 | パスキーが1つも登録されていない状態では、パスワードサインインを無効化できない。UI で不可能にし、サーバー側でも拒否する |
| FR-A5 | パスキーを全失した場合に備え、**CLI でパスワードサインインを再有効化**できる。その旨を設定画面に明記する |
| FR-A6 | サインイン画面以外の全ページは認証必須。未認証ならサインインへリダイレクトする |

判断の根拠は `docs/adr/0002-password-sign-in-toggle.md`。

### 5.2 メモの作成・編集

| ID | 要件 |
| --- | --- |
| FR-M1 | Memo を作成・編集・削除できる。保存には**本文1文字以上**を必須とし、タイトル・タグ・レース情報・参照はすべて任意 |
| FR-M2 | 保存は**明示的な操作**で行う。自動保存はしない |
| FR-M3 | 未保存の変更がある状態で画面を離れようとしたら警告する |
| FR-M4 | 本文は Markdown 記法で保存し、表示時にレンダリングする。対応記法は見出し・箇条書き・強調・リンクの最小集合とする |
| FR-M5 | タグはメモ編集画面から**インラインで作成**でき、種類（馬 / 人 / 主題）を選ぶ。既定は主題 |
| FR-M6 | レース情報は任意。開催日・競馬場・レース番号を選択し、レース名を自由入力できる |
| FR-M7 | 参照はメモ編集画面から**検索して選ぶ**。複数指定できる |

### 5.3 一覧・検索

| ID | 要件 |
| --- | --- |
| FR-L1 | ホームは**タイムライン**。投稿日時の降順で並ぶ（編集しても並び順は変わらない） |
| FR-L2 | 一覧は無限スクロール。一度に20件ずつ読み込む |
| FR-L3 | 検索は**部分一致**。本文・タイトル・タグ名を対象とし、順位付けはせず新しい順に返す |
| FR-L4 | タグで絞り込める。複数タグの同時指定ができる |
| FR-L5 | タグページは、そのタグが付いた Memo を時系列で並べたもの（E1: 馬ごとの履歴） |
| FR-L6 | レースページは、同じ開催日・競馬場・レース番号を持つ Memo を並べたもの（E2: レースごとのメモ一覧） |
| FR-L7 | メモ詳細では、参照元・参照先の両方をたどれる |
| FR-L8 | タグ一覧画面から、タグページへ移動できる |

### 5.4 設定・データ

| ID | 要件 |
| --- | --- |
| FR-S1 | パスキーの登録・改名・削除ができる |
| FR-S2 | パスワードサインインの有効／無効を切り替えられる（FR-A3） |
| FR-S3 | 全メモ・タグ・参照・レース情報を **JSON でエクスポート**できる。設定画面のボタンからダウンロードする |

## 6. 非機能要件

| ID | 要件 |
| --- | --- |
| NFR-1 | ホスト名は `turf-notes.koralle-mgmg.com`。**パスキーの rpID がドメインに紐づくため、後から変更しない前提**で最初から確定させる |
| NFR-2 | PC・スマートフォン両対応のレスポンシブ。入力画面はモバイル優先で設計する |
| NFR-3 | オフライン対応は行わない。書きかけの退避も行わない（FR-M2/M3 で担保する） |
| NFR-4 | UI は日本語のみ。日時の表示・解釈は JST 固定 |
| NFR-5 | 想定件数は数千件程度。この規模で検索・一覧が実用的な速度で動くこと |
| NFR-6 | 削除は論理削除。ゴミ箱画面は作らない |
| NFR-7 | 認証必須。CSRF 対策は pantry と同じ方式（同一オリジン＋ oRPC の定義済みエラー）に従う |

## 7. スコープ外

以下は**作らない**。将来必要になった時点で別途判断する。

- 印（◎○▲△×）・買い目・結果・払戻・収支／回収率の記録と集計
- 画像・ファイルの添付
- リマインダー・次走通知
- マルチユーザー、共有、公開ページ
- オフライン対応、PWA 化
- 外部データ（出馬表・オッズ・結果）の取り込み
- ゴミ箱画面、完全削除の UI
- WYSIWYG エディタ、リッチテキストの貼り付け
- ブラウザ拡張、モバイルアプリ

## 8. 技術構成

pantry とほぼ同じ構成を踏襲する。

| 層 | 採用 |
| --- | --- |
| フロントエンド | TanStack Start + TanStack Router + TanStack Query、React 19 |
| スタイル | Panda CSS（PostCSS プラグイン）、react-aria-components、lucide-react |
| フォーム | Conform + Valibot |
| API | Hono + oRPC（contract-first）、`apps/api` を別 Worker にして Service Binding で接続 |
| DB | Drizzle ORM + libSQL/Turso。スキーマとマイグレーションは `packages/db` |
| 認証 | Better Auth（メール+パスワード、パスキー）＋ admin プラグイン |
| ID | Memo は UUID v7。Tag は整数の自動採番 |
| ツール | TypeScript、oxlint/oxfmt（Ultracite）、knip、lefthook |

pantry から**持ち込まない**もの: web 側の未使用な DB 依存、`DynamicLink` の過渡期コード、サインアップを UI でしか止めていない状態。

## 9. 品質基準

| 層 | 内容 |
| --- | --- |
| 単体テスト | タグの正規化・一意性、メモの並び順・検索条件、参照の整合性、認証の可否判定 |
| DB 統合テスト | Testcontainers で実 libSQL を立て、本番マイグレーションを適用して検証する |
| Storybook | 共有コンポーネント＋状態の多い2〜3画面（サインイン、一覧の空・エラー等）。全画面の Route stories は作らない |
| CI | check / typecheck / test（単体＋DB統合）/ build / build-storybook |
| 手動確認 | サインイン → 作成 → 検索 → タグ絞り込み → レースページ → 参照 → 編集 → 削除 → エクスポート |

## 10. 決定の根拠（却下した選択肢）

| 論点 | 決定 | 却下した案と理由 |
| --- | --- | --- |
| レースの持ち方 | 3つ組を Memo に持つ | 独立テーブル（作成ステップが挟まり書く摩擦が増える）／レース名タグ（平場に名前がない） |
| 馬・人の持ち方 | Tag で表す | 専用エンティティ（マスタ維持のコストが個人用途に見合わない） |
| タグの種類 | 3種（馬/人/主題） | 種類なし（タグ一覧が混ざって探せない） |
| メモ間の参照 | 専用欄＋ラベルなし | 本文中の `[[...]]` 記法（パースが壊れやすく、記法の学習コストがある） |
| タイトル | 任意＋1行目フォールバック | 必須（毎回題名を考える摩擦）／なし（参照 UI が本文の切り貼りになる） |
| 外部データ | 取り込まない | JRA-VAN（Windows 専用 ActiveX）、スクレイピング（規約で制限） |
| 印・買い目・収支 | 作らない | メモが台帳に変質し、入力コストが跳ね上がる |
| 保存 | 明示操作 | 自動保存（オフラインなしの前提では「保存したつもりで消える」事故を生む） |
| エクスポート | JSON | Markdown（タグ種類・参照方向・レース3つ組が欠ける） |
| Worker 構成 | 2 Worker + Service Binding | 1 Worker + D1（構成は素直だが pantry の資産を再利用できない） |

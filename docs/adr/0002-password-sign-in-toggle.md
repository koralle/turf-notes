# パスワードサインインの可否をユーザー設定とし、アプリ層で拒否する

Better Auth の `emailAndPassword.enabled` はデプロイ時の設定であり、ユーザー単位では切り替えられない。turf-notes は「パスキーを主、パスワードを従」へ段階的に移行したいので、`users` に可否フラグを持たせ、無効のときはサインイン API がパスワードを受け付けない（**アプリ層で拒否する**）。パスキーが1つも登録されていない状態では無効化を許さず、パスキーを全失した場合はサーバー上の CLI で再有効化する。

## Considered Options

- **`emailAndPassword.enabled` を切り替える**: ライブラリの想定経路だが、デプロイ時の設定なのでユーザーが UI から切り替えられない。
- **復旧コードを発行する**: ユーザー自身で戻せるが、発行・保管・使用の3つを実装する必要があり、単一ユーザーのアプリには過剰。
- **無効化を許さない**: 実装は最小だが、「パスキーを主にしたい」という要件を満たせない。

## Consequences

- 有効/無効の判定が Better Auth の外にあるため、サインイン経路を増やすときは必ずこのフラグを確認する必要がある。
- パスキーを全失するとサーバーにアクセスできる人しか復旧できない。UI 上でその旨を明示する。
